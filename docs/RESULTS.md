# 検証結果

元の経路（cadmpeg 5af95421 ＋ 拡張 → CADIR → 参照書き出し）と本エンジンを比較した結果です。
検証データは実務で使われている部品・アセンブリ 73 件（重複を含む）で、リポジトリには含めていません。
以下ではファイルを記号（部品 A〜F、アセンブリ D）で表します。

## 変換精度

### GLB（最終出力）

`tools/glb_all.sh` で、参照書き出しが出力した GLB とバイト単位で比較しました。

| 結果 | 件数 |
| --- | --- |
| バイト単位で一致 | 71 |
| どちらも変換失敗（終了コード 3、同じ理由） | 上記 71 件のうち 2 件 |
| 再生成の参照とバイト単位で一致 | 1（部品 R） |
| 不一致 | 1（部品 B） |
| 終了コードの不一致 | 0 |

- **部品 R** は保存済み表示メッシュが古いファイルで、B-rep から再生成されます。参照経路
  （B-rep → STEP → OCCT のテッセレーション → `replace_surface`）で作った GLB とバイト単位で一致しました。
- **部品 B** は、頂点座標・法線・マテリアルは一致し、81,186 頂点のうち 92 三角形（276 インデックス）が
  別の色のグループに入っています。表示メッシュ 2 件の所有者の面を解決できないためです。原因は下記の
  「ブレンド面の近似」です。

GLB の書き出し部だけを単独で検証するため、cadmpeg の CADIR を入力にした `sldprt-glb from-cadir` でも比較し、
成功した 71 件すべてでバイト単位で一致しました。JSON の数値表現（`float.__repr__` 互換）は 199,307 個の値で
ファジングし、不一致は 0 件です。

### ブレンド面の近似

cadmpeg はブレンド面を数値的に解いて NURBS で近似します。本エンジンはこの処理
（`blend_surface` / `blend_fit`）を移植しましたが、残る差分の面は、最近点探索が許容差 1e-10 に対して
約 1.3〜1.4e-10 で止まるなど、収束判定のしきい値のちょうど境目にあります。cadmpeg は内積・ノルムを
正しく丸める専用の計算と `libm` クレートの三角関数を使っているため、浮動小数点の丸めまで一致させるのは
現実的ではありません。しきい値を 2 倍または 1/2 にすると結果が入れ替わることを確認しています。

## 速度

同じマシン（WSL2 Ubuntu 26.04、32 論理 CPU）で、各ファイル 3 回実行した最短時間です。
元の経路は参照書き出しから cadmpeg の Windows リリースビルドを呼び出した時間、本エンジンは 1 CPU に固定
（`taskset -c 0`）した時間です。どちらも GLB の出力までを含みます。

| | 元の経路 | 本エンジン（1 CPU） | 比 |
| --- | --- | --- | --- |
| 71 件の合計（アセンブリ D を除く） | 90.8 秒 | 5.67 秒 | 16 倍 |
| ファイルごとの比（中央値） | | | 21 倍 |
| 部品 A（最大の部品） | 26.6 秒 | 1.99 秒 | 13 倍 |
| 部品 C | 17.9 秒 | 0.73 秒 | 25 倍 |
| 部品 B | 11.3 秒 | 1.30 秒 | 8.7 倍 |
| アセンブリ D | 125 秒 | 0.33 秒 | — |

- アセンブリ D は、この環境の Windows 版 cadmpeg だけが極端に遅い（Linux 版では約 19 秒）ため、
  合計から除いています。
- 本エンジンは 1 CPU に固定しても固定しなくても、ほぼ同じ時間です。
- ブレンド面の近似を追加したことで、全体の時間は約 16% 増えました（部品 A では 1.44 秒 → 1.99 秒）。
  プロファイルはまだ取っていません。

### ビルド時間

| | 元の経路（cadmpeg） | 本エンジン |
| --- | --- | --- |
| クリーンビルド | 約 35 分 | 24 秒（32 並列）／1 分 43 秒（1 並列） |

本エンジンの時間は CMake の構成（約 9 秒）を含み、OCCT と zlib はシステムのパッケージを使っています。

## cadmpeg との差異

GLB に影響しないもの、または影響する入力が検証データにないものです。

- コンテナー末尾の検証を緩めています（cadmpeg が拒否する一部のファイルも読みます）。
- 損失ノート（loss notes）と処理量の上限（budget）は出力しません。アセンブリの入れ子の上限 128 だけを
  実装しています。
- 解決できないフィーチャー外観の衝突（unresolved feature-conflict appearance）は出力しません。
- 所有者の解決では、ボディの変換を常に単位行列として扱います。
- 面の許容差による拒否（face tolerance refusal）は移植していません。辺の許容差も出力しません。
- キャッシュセルの `_DL_VERSION_` 名は `entry_names` に追加しません。
- 仮想部品の文書は解析しません。
- 交差曲線以外の曲線上のトリム曲線は、範囲だけを適用し、端点を検証しません。
- NURBS のオフセット面とブレンド面を支持面とする SP_CURVE は近似せず、曲線の種類は `unknown` になります。
- 表示状態のランク 3（`moCompFeature_c`）の対象面は、フィーチャー履歴ではなく面の FACE_ID_2001 の
  （ソース、タイムスタンプ）で近似しています。
